# BrainSync P300 主工作站

更新：2026-09-06。主版本为本目录，旧`BrainSync_Tool_0cb0_V2.2.5_20260729`目录仅作历史来源。
本版本保留设备连接、波形、阻抗、采集、BIDS、恢复和高级任务，并加入个体校准、模型保存加载、
新45闪烁测试自动判定和目标反馈。实际操作仍需有效硬件与合格记录。

## 启动

- `Launch_BrainSync.cmd`：设备模式，使用上次保存的串口USB或BLE方式；首次默认BLE。
- `Launch_Mock.cmd`：模拟设备模式，可生成明确标记为模拟数据的EDF，不能作为真人性能。

模拟阻抗由固定公式生成，约1.9–4.7 kΩ，不随电极接触变化。模拟窗口标题和阻抗面板
明确标注来源，模拟值不会判为接触质量合格；检查真实电极应使用设备模式入口。

两个入口使用本目录`.venv/Scripts/pythonw.exe`，当前Python3.10.20。
依赖由本目录`pyproject.toml`和`uv.lock`固定；首次部署/更新执行`uv sync --locked`。
默认只用本目录`.venv`，不扫描其他项目或临时SDK目录。
本机已验证NumPy1.26.4、PySide6 6.11.2、qasync、pyedflib与brainsync_sdk可加载。
不把SDK的Python3.10路径注入n2p3算法解释器。

也可从终端运行并查看启动错误：

```powershell
.\.venv\Scripts\python.exe run_gtn_workstation.py --mock
```

串口与BLE采集均固定为 **250 Hz**，界面只显示固定值，底层也拒绝其他采样率。
串口端口、BLE名称和各自增益分别保存到`device_connection.json`，切换模式不混用地址。
可用`Launch_BrainSync.cmd --transport serial --address COM7`直接启动串口模式；
BLE使用`--transport ble --address BrainSync`。省略地址时使用该模式保存的地址；没有保存地址时，
SDK自动发现串口或使用默认BLE名称。连接中或已连接时不能修改连接方式与地址，断开后可切换。

显式SDK位置可用`--sdk-site-packages`指定。原生SDK设备测试仍需真实硬件；
模拟回放、软件单元测试和已有公共ERP成绩不能代替实机验收。

## 校准与猜数字

REF接左耳耳垂耳夹，规范声明`left earlobe`，不是T7/T3或右耳垂；EEG与单端HEOG共用该采集REF。
`models/acquisition_reference.json`与后端导出的物理合同一致。原生七导保留采集参考，
本人LDA默认走此路径；既有源模型按其合同显式使用Cz六导。两种方法分别保存参考选择，
原生选择拒绝Cz质量模型，不能只改标签来复用另一种参考的QC或个体模型。
当前更正后的质量文件及历史更正说明见后端`doc/evidence/brainsync_reference_20260908.zh.md`。

1. 在“设备与质量”连接设备并检查通道与接触。采集布局为
   `Fz,Cz,P3,Pz,P4,PO8,EOG,Oz`，分类输入为七EEG；EOG单独保留，不参与头皮卷积或CAR。
2. 在“校准与推理”的“本人校准”选择受试者和目标数字。“采集校准”设置10block×45闪烁，
   每份session只有一个目标；九个数字分别采集可得到4050trial，其中450target。
   目标在录制结束后确认，晚确认时间真实保存。
3. 选择同一人的已确认记录，点击“校准并保存”。源模型微调需要至少两份独立session，
   固定本人LDA可以使用一份含两类的session。被排除或缺文件的记录不会作为可用校准输入。
4. 默认源模型为`models/source/bnci_cz6_seed20260906_A01.pt`，是公开ERP研究初始化，
   配套显式Cz共同参考。它不是已验证的BrainSync冠军或某人的个体模型；
   不兼容的源checkpoint会明确报错，不静默降级为LDA。
5. 眼电回归复用n2p3模块。神经网络只在内部训练session拟合EOG并冻结，
   贯穿配方选择和完整校准重训；固定LDA可用全部授权校准session拟合。
6. 保存的个体模型自包含权重、输入统计、EOG、参考、通道、participant和校准范围。
   “加载模型”通过`inspect`核验后恢复所属受试者与校准报告，保存图标可另存完整模型。
7. 在“猜数字”点击“开始新测试”。新session固定1block×45闪烁，完成并保存raw后，
   应用先调用模型判定，再提示确认真实目标。显示九候选分数、R1–R5和实际命中反馈。

分数是聚合的二分类证据，不是已经校准的概率。缺覆盖或并列会拒判，失败和停止也保留记录。
校准完成直接展示内部验证AUC、数据采用量、训练曲线和候选比较；内部验证和最终全量训练
分开显示，旧包未保存的曲线不补造。方法、参考、眼电、QC和路径位于右上角“校准与数据设置”，
通用脚本入口位于“研究算法任务”。日常操作不需要填写输出目录，日志默认收起，失败时展开。
推理列表只展示当前模型所属用户、相同模拟声明、校准就绪后的独立45闪烁记录；没有候选时隐藏选择器。
新结果展示九候选证据柱状图、R1-R5、有效闪烁数和拒判原因；换模型或开始新推理时清空旧结果。
这是block完成后的自动推理，不是每个SDK chunk的流式神经网络推理。
模型拒绝不同participant、已用校准记录、时间逆序、输入合同或模拟声明不符的记录。

## 数据与环境

模型后端默认寻找同级`D:/BCI/n2p3-net`，使用它的`.venv`与
`experiments/brainsync_model_task.py`。算法项目位置可在模型区域设置按钮中修改。
前端`ModelTask`构造结构化argv，并核对结果的schema、请求编号、状态、会话、受试者和模型摘要。
`ModelJobRunner`执行、读取进度并取消整个子进程树；窗口关闭和应用直接退出均等待统一shutdown。
每个模型任务都有独立`models/runs/<任务>/`目录，包含`backend_task.json`、`backend.log`
和`summary.json`；校准产生`personal_model.pt`，测试确认另写`feedback.json`。
原始模型结果不会被反馈或重训练覆盖。

“校准与数据设置”可选择CPU、CUDA GPU或自动，设备由后端自己的环境解析并写入任务结果。
默认CPU；显式CUDA不可用时直接报错。该设置用于校准、模型检查和推理，LDA仍在CPU拟合。
本机校准记录目录已指向后端更正后的`experiments/runs/brainsync_p001_20260907/inputs/`；
新采集后仍切换到该次记录目录。旧原始记录不因路径修改而获得模型输入资格。
四份旧规范记录缺少EOG接法声明，本机配置关闭自动EOG；新采集可在接法明确后显式开启。
固定本人LDA的QC/EOG只使用完整授权校准范围，不进行内部选方；源微调的不兼容和全部候选失败
均明确终止，开启QC不会改成LDA成功。研究算法任务的通用接口与本人校准保持各自用途。

每次实验完成落盘后，后台自动生成数据质量报告；顶部“查看质量报告”直接显示文字结论、
原始信号/频谱、逐导epoch幅度和完整闪烁覆盖图。分析页“质量报告”也可用于已有记录。
冻结QC按当前配置或推理个体包读取，没有冻结QC时明确标为基础诊断，不在新测试中拟合门限。
报告支持进度、取消及重新生成，版本位于会话`analysis/quality_reports/`，不改写原始数据。
队列在采集和前台模型任务空闲时启动；后台报告不锁定后续采集，关闭应用会停止报告进程。

采集目录可在实验参数或模型数据目录中选择。原始回调采样录制保留于`sourcedata/brainsync`，
完整BIDS raw保留休息段，分析层再排除相交epoch。旧PO7/EOG命名或错误坐标的记录不会
静默变成当前七EEG/EOG资料；未改写既有原始数据。

## 录制与质量

实验屏按ESC暂停，菜单提供继续、终止并保存、废弃本次测试。
暂停期间不向EDF追加样本，连接保持；继续先恢复写入并提示倒计时3秒，再恢复刺激。
被中断的试次有独立attempt与无效标签，恢复后以相同数字重做，保持原候选排程。
结束保存标记为aborted，废弃删除本次会话数据并只保留编号/时间审计记录。
暂停区间、恢复倒计时、试次无效状态写入事件日志与EDF注释，BIDS通过
acquisition_boundary和segmented_recording声明样本断点；后端按段滤波并排除跨断点epoch。

设备状态机及采集会话生命周期共同构成操作权限依据，见[STATE_MACHINE.md](STATE_MACHINE.md)。
`RecordingSession`统一样本支持、暂停/恢复账本及EDF/BIDS收尾；录制收尾也属于busy状态，
不能在旧文件尚未完成时开启下一次采集或模型任务。目标确认采用可恢复提交；写入失败后，
在分析页点击“恢复未完成操作”，完整提交前不允许该会话进入模型。原事件历史冲突时不会自动覆盖。
目标确认期间不启动新实验或全屏练习。最后刺激后保留完整ERP尾窗，再关闭录制。

串口与BLE共用本地EDF录制器、样本时钟、暂停恢复和BIDS导出；不再启用SDK原生EDF分支。
正常调度下每5秒追加电压及样本时钟联合检查点，最终尾段也持久化。
EDF由共享writer原子发布；并发finalize在锁外等待，失败可重试，紧急保存不会重复持锁等待。
停止与自动恢复互斥，失败订阅清理不重复注册。恢复成功不抹去已记录的连续性gap。

阻抗检测会改写设备参数，后续预览和录制先重新应用250 Hz及所选增益。
串口必须读回确认采样率；BLE仅在读回超时且固件请求证明链路仍存活时保留明确的读回不可用声明。
该声明不代表增益已读回验证。取消连接保留原生请求所有权，迟到句柄释放后才允许重连；
关窗会等待连接请求及其清理结束。原生命令永久不返回时，窗口保持关闭中，不能假报清理完成。

EEG/EOG预览滤波只影响波形显示，不改变raw。软件repaint标记不等于光学触发，
主机marker到设备样本时钟的偏移尚需实机测量；不声称已实现硬件级时序精度。
阻抗显示与眼电回归不是有效P300或成人效能的证明。

## 验证与历史

阻抗检测持续传输，停止或关闭检测窗时依次停止传输、退出检测模式、释放回调。
启动命令最长等待8秒，单条清理命令最长等待3秒；连续10秒没有阻抗回调会报告数据中断。
SDK调用在后台执行。超时后若命令仍未返回，保留待恢复状态，避免与新命令并发操作设备。
错误窗口直接显示失败阶段与原因，主窗口仍可断开重连。
启动器运行时会将界面日志、阻抗命令阶段和异常栈写入`logs/workstation.log`，
即使尚未开始录制也会保存；单文件约2 MB，保留3份滚动备份。

## 2026-09-16逻辑修复

预览滤波按设备实际采样率执行，采用二阶节避免高采样率眼电滤波数值发散；不写入raw。
配置与预览切换期间不能开始冲突操作；采集准备阶段可以停止，失败准备不把目标数字带入下一次采集。
负阻抗不判合格。恢复后迟到的废弃操作不会改变当前录制。

设备掉线先保留已接收样本，保存失败时禁止新录制覆盖旧缓冲。超时的原生命令未真正结束前，
不并行重试或启动新设备操作。会话占用由OS维护，其他实例不能恢复或确认活动会话；崩溃后可恢复。

报告重试保持原冻结模型与处理参数，损坏参数明确失败。结果解析失败不会保留旧数字或就绪模型；
事后反馈核对原请求/会话/受试者/已确认目标，无预测时显示“未形成有效判定”，correct为null。
