## 可保留的增强

| 能力 | 新版实际变化 | 结论 |
|---|---|---|
| BLE录制 | `.part`增量检查点、离线恢复、先落盘再停止、真实回调数量参与ready判断 | 有工程价值，但并发finalize存在下述缺陷，不能直接按报告声称完全可靠 |
| 清理SDK | 工厂调用在线程隔离、超时、失败兜底 | 改善原生阻塞影响；无实机/SDK测试，不作永不冻结承诺 |
| 预览 | EEG/EOG分开预览滤波、通道角色显示和环境变量 | 预览不是保存的原始数据或模型输入；可保留而不改变模型预处理合同 |
| 模型任务 | 下传EEG/EOG类型与索引给子进程 | 有用接口增强；仍读取已保存session并启动外部命令 |
| 刺激 | 调度核心与旧版一致，每9次独立随机排列 | 45闪烁仍严格R5，10block为450闪烁；纯函数9000个block验证通过 |
| 目标标签 | session结束后允许操作员异步确认 | 科学上合法，应检查标签实际可用时间，不强迫确认发生在录制结束前 |

两版每session仍只有一个目标；4050trial可用九个完整450trial session实现。
若将九目标交错成10轮，每目标每次1block，应对应90个独立session或另建显式decision合同，
不能在当前单目标session中悄悄切换目标并保持一个`thought_digit`。

## 新版风险与不兼容

### 1. 七EEG加独立EOG声明未合入

新版`gtn_workstation/models.py`及`channel_assignments.json`使用
`Fz,Cz,P3,Pz,P4,PO8,PO7,Oz`，将第七槽`PO7`设为EOG，但仍给它头皮坐标。
当前n2p3合同是`Fz,Cz,P3,Pz,P4,PO8,EOG,Oz`，不猜测EOG方向与头皮位置。
两版实际分类器目标都是七EEG，但元数据的物理含义不一致。

新版七EEG坐标与MNE `standard_1005`未配准原坐标最大差约`1.39e-17 m`，却声明为head；
与`info.set_montage`变换后的head坐标最大电极位移约`0.05687 m`。
旧修正版与后者最大轴差约`5.44e-9 m`。这是实际坐标系错误，不只是名称不同。

使用新版默认montage执行当前生产者→n2p3集成探针，实际在BIDS写入时因EOG/PO7名称
不一致失败，见[探针记录](../assets/technical_audit_20260906/newest_producer_probe.xml)。
这首先证明默认配置不兼容；实际新版记录也使用同一PO7/type=EOG声明，不能靠改文件名准入。
后续应在明确硬件接线后同步通道角色与坐标来源，保留raw来源，不能静默重命名历史数据。

### 2. 并发finalize会持锁等待

新版`runtime.py`的`LocalEdfRecorder.finalize`在持有`_lock`时等待`_finalize_done`，
而首次导出线程完成后还要取得同一锁才能设置完成标志。停止超时后的同步emergency save
可以进入该分支。无GUI、无真实文件写入的线程反例已复现：将等待上限缩为0.25秒，
写盘函数已经返回，首线程仍额外受阻约0.211秒，直到第二调用超时返回`None`才完成。
真实常量为30秒。因此新的抢救路径仍可能把UI阻塞到超时，报告里的绝对保证不成立。
后续修复应在锁内只读取状态，在锁外等待，并保留首次导出的结果和错误。

### 3. 样本时钟问题为新旧共有

录制零点取“程序检查到已有回调数据”的主机monotonic时刻；EDF包含首批完整样本。
`_on_eeg_batch`没有保存设备sample clock与主机marker之间的映射。缓存、传输及轮询
延迟可能形成事件到样本的偏移，现有readiness判断不证明精确对齐。
这不是已量化的偏移结论，需回放/实机时钟对照；软件repaint仍不等于光学发光时间。
恢复订阅前记录的continuity gap必须继续影响准入，不能因恢复成功而抹去缺失时间。

## 新增离线P300脚本

`p300_digit_decode.py`、`p300_quality_check.py`及绘图脚本没有接入N2P3 checkpoint或
SubjectAdapter，不读取新增模型任务环境变量，也不导出/加载个体模型。其结果不能视为
本项目“本人校准→冻结→新一轮实时推理”的证据。

| 问题 | 实际实现与影响 |
|---|---|
| 基线窗错误 | `PRE=+0.2`却构造`slice(0,-50)`；250Hz、250样本epoch实际减`[-0.2,0.6)s`均值，包含P300，非刺激前基线 |
| LOBO冒充未来推理 | 每折用其余所有block训练，早期预测使用后续标签；跨block累计来自不同模型；整会话双向滤波还使用未来样本 |
| 失败分母和候选集缩小 | QC后没有target trial的block被跳过；仅排序仍有样本的数字，不足九个仍报选择结果；并列按插入顺序择胜 |
| 标准化范围 | 先按整session统计再LOBO，留出block参与拟合；留出block自身score标准化还改变跨block证据权重 |
| 置换检验错误 | 200次只是在其他8个伪目标中抽取，不是有交换性依据的完整置换零分布；p值可报0 |
| 源码与产物漂移 | 当前JSON仅含P004，脚本固定P001-P003，绘图颜色表无P004；标题/坐标上限硬编码，不能直接重现现有结果 |
| 输入与环境 | 固定假定250Hz、微伏和电极索引；未验证EDF labels/合法session；使用NumPy 2已移除的`ndarray.ptp`，项目环境也未装其`pyedflib`依赖 |

基线数值反例：epoch覆盖`[-0.2,0.8)s`，只给样本`[125:150)`即刺激后`[0.300,0.400)s`
赋10微伏；错误均值`25×10/200=1.25`微伏，正确刺激前50样本均值为0。
双向滤波的未来脉冲影响过去也由纯数值反例确认；这些验证没有拟合真实数据模型。

可以保留时间窗特征、block质量诊断和排名图的研究目的；实现应复用n2p3已有输入合同、
sklearn收缩LDA和完整候选聚合，不能直接迁入上述独立脚本作为产品推理器。

## 实际记录与n2p3联动

新目录顶层已有7份session：4份声明completed、confirmed、BIDS raw、continuity passed，
3份为recording_error/source acquisition。不能继续笼统称本机没有记录；4份应列为候选
采集资料，尚未完成物理通道、参考、时钟、信号质量和成人研究准入。

审查时4份completed记录的确认时间比ended晚约3.815/6.101/7.414/5.789秒，旧n2p3
校验因此拒绝。这是新版有意采用的先结束后确认流程，不应单独判作泄露或坏数据。
n2p3需以`max(session_end, target_confirmed)`作为校准数据与标签的就绪时刻，
后续测试必须晚于该时刻；测试自己的事后标签只用于评分。

同时发现n2p3的EOG评估入口把复合decision group编号传给需要真实session ID的预算
检查，可能拒绝合法EOG校准。应从实际calibration mask选择结构化session字段，
不解析group字符串或放宽预算检查。修复和最终测试在[整体审计](technical_audit_20260906.zh.md)记录。

## 合并顺序

1. 用当前七EEG/EOG物理合同和已配准坐标作为共同数据接口；明确新版真实接线和参考。
2. 保留新版录制恢复、真实回调计数、通道角色环境变量，先修并发finalize持锁等待。
3. 完成n2p3晚确认时间与EOG session预算调用修正，再验证两个版本的生产者/消费者。
4. 核实设备样本时钟与marker映射，检查7份已有记录；不把metadata成功当全部信号合格。
5. 继续个体模型导出、校准内部选择和无标签在线R5接口；新增离线脚本不代替该链条。

比较之后已按上述顺序整合新版app；未把两个目录互相覆盖，也未改写原始记录。
SDK/Python3.10工作站与本项目模型`.venv`仍是两个执行环境，通过结构化进程接口通信。
