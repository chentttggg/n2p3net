## 1. 目标与决策依据

为路线 A 构建源域 cache：**BI2015b（44 人，32 导湿电极，2015）→ BI2014a（64 人，16 导干电极，2014）**。

选 BI2015b 而不是别的，是因为它同时满足四条：

| 条件 | BI2015b |
|---|---|
| 候选身份可恢复 | ✅ 事件行含 20-25 行 / 40-45 列 / 60-65 target 行 / 80-85 target 列（45 种编码） |
| 通道交集足够 | ✅ 与 bi2014a 交集 **16 导**（2014a 的蒙太奇是 32 导的子集；通道选择不丢失，CAR 任务保留仍需验证） |
| 跨年（被试重叠风险低） | ✅ 2015 vs 2014 |
| 域语义可命名 | ✅ 湿 vs 干电极 + 年份批次 |

（BI2015a / BI2012 / BI2013a 全部因缺 flash group code 被否，见前置文档 §5.2b。）

## 3. 构建器设计（待实现）

### 3.1 总体路线

新建 `src/data/bi2015b_candidate.py`，**模式复用** `bi2014a_candidate.py`（selection 切分、candidate 成员校验、repetition index 派生、timeline 组装），差异点：

| 环节 | bi2014a（现有） | bi2015b（待建） |
|---|---|---|
| 数据源 | 每被试一个 CSV（19 列：time + 16 EEG + group code + flag） | 每对一个 MAT（66 行 × N），需分人 |
| 通道 | 16 导（硬编码 `BI2014A_CHANNELS`） | 32 导（moabb 定义，见 §3.2） |
| 采样率 | 512 Hz | 512 Hz |
| 分人 | 无 | `subject % 2` 取 `D[1:33]` / `D[33:65]` |
| 事件列 | col17 + col18 | 行 65（需确认是否要 `D[-2]+D[-1]`） |
| 条件筛选 | 无 | **必须只取 1-target 条件**（见 §3.3） |
| timeline | `observed_only_timeline`（complete=False） | 建议走 `ScheduledEventTimeline`（显式 rep 链），与 `bnci2014_008_candidate.py` 一致 |

### 3.2 32 导通道名（moabb 权威，2014b/2015a/2015b 三者完全相同）

```
Fp1 Fp2 AFz F7 F3 F4 F8 FC5 FC1 FC2 FC6 T7 C3 Cz C4 T8
CP5 CP1 CP2 CP6 P7 P3 Pz P4 P8 PO7 O1 Oz O2 PO8 PO9 PO10
```

### 3.3 条件筛选：2-target 与 row_column 契约冲突

BI2015b 四个条件含 **1-target 与 2-target** 两种（docstring：1 或 2 Target）。
row_column 判定是「target row ∩ target col = 唯一格子」——**2 个 target 时交集不唯一，契约失效**。

处理方式（二选一，需先探明 s1–s4 与条件的映射）：
- **保守（推荐）**：只构建 1-target 条件（Cooperation-1Target / Competition-1Target），丢弃 2-target；
- **进阶**：先验证判定语义能否扩展到 2-target（目标集合判定而非单格），若可则全部纳入。

⇒ **构建第一步必须先识别 s1–s4 各自对应哪个条件**（通过每个 block 内 target-row/target-col 码的数量关系：1-target 块内每轮各 1 个；2-target 块内会出现 2 个不同的 target row 码）。

### 3.4 域对齐

构建后经 `src/data/domain.py` 的现成契约对齐：

```
ensure_native_reference_selection(dataset, <16 导公共子集>)   # 默认；参考不一致则 fail-closed
# 或显式：ensure_common_channel_average_reference(dataset, <16 导公共子集>)
ensure_epoch_dataset_namespace(dataset, "bi2015b")
annotate_source_domain(dataset, "bi2015b")
project_binary_evidence_source_view(...)      # 可选：若走 binary_evidence 合同
```

入口 `experiments/prepare_multidomain_source.py --source bi2015b=<cache> --target-channels "<16 导>" --event-contract ...`；
默认 `--reference-mode native_preserve`，CAR 必须显式 `--reference-mode common_average`。

**16 导公共子集**（= bi2014a 全蒙太奇，已确认是 32 导的子集）：
`Fp1 Fp2 F3 AFz F4 T7 Cz T8 P7 P3 Pz P4 P8 O1 Oz O2`

## 4. 执行步骤（建议增量）

| 步 | 内容 | 产出 | 验收 |
|---|---|---|---|
| **P0** | **单对 pilot**：只构建 group_01 的两人，跑通 MAT → 单人 → 事件解析 → selection → candidate 校验全链路 | 2 人 mini cache | `candidate_audit` 全绿；rep 分布与抽样普查（rep 1–6）一致 |
| P1 | 条件映射：识别 s1–s4 各对应哪个条件，确认 1-target 筛选规则 | 映射表 | 每 block 的 target-row/col 计数自洽 |
| P2 | 全量构建 22 对 = 44 人 | BI2015b candidate cache | attestation 可验证；selection 数/rep 分布报告 |
| P3 | 统一到 16 导公共子集 + CAR（参考/蒙太奇规范化） | 多域 source cache | `domain.py` 契约校验通过（含 CAR 数值校验）；不单独等同于 feature alignment |
| P4 | 与 BI2014a target cache 组装 plan（P0/P1 首次启用） | `plan_bi2015b_to_2014a.json` | dry-run 绿 |

**P0 pilot 优先**——先用 2 人验证全链路，避免 44 人全量构建后在最后一步才发现语义问题。

## 5. 已知风险与待定项

| # | 风险 | 处置 |
|---|---|---|
| R1 | **hit@R 不可用**：BI2015b 侧 rep 1–6，target（BI2014a）侧仅 5.2% 达 8 层 | 本轮主指标走 **AUC**；hit@R 降到 R=2（68.1% eligible）作辅助。深 R 的 estimand 留给 GTN 路线 |
| R2 | 2-target 条件与 row_column 冲突 | P1 先做条件映射，只纳入 1-target |
| R3 | 被试重叠（2014a × 2015b 跨年，风险低但非零） | 无元数据可比对；跨年已是最优规避，记录为已知不确定 |
| R4 | 控制码 102/105–111/160–185 语义未知 | P0/P1 阶段按时序位置反推（出现频率、block 边界相关性）；**不猜测、不硬编码未知语义** |
| R5 | 双人事件通道共享（行 65 是两人共用还是各一行？） | P0 时对比行 64/65 的内容差异再定 |
| R6 | 构建器若走 `observed_only_timeline` 会硬编码 `complete=False` | 建议走 `ScheduledEventTimeline`（显式 rep 链），与 `bnci2014_008_candidate.py` 一致，避免重蹈 BI2014a 的 timeline 字段缺口 |
